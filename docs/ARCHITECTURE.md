# 架构

## 分层

```
app.c        窗口、立即模式绘制、输入分发、消息循环
  |
session.c    连接生命周期、乐观显示副本、动作入口、刷新频率统计
  |
device.c     动作计划执行器、量纲换算、写入护栏
  |
transport/   通用 Modbus RTU 主站、Win32 串口字节流后端
```

低层不依赖高层。`transport/` 不包含产品名称与业务名词，可以独立发布。`device.c` 只依赖 `transport/`，`session.c` 只依赖 `device.h` 与 `ui.h`，`app.c` 只依赖 `session.h` 与 `ui.h`。

## 状态归属

| 状态 | 持有者 | 谁能修改 |
| --- | --- | --- |
| 串口句柄、唯一未完成请求、接收缓冲 | `transport/` | 仅通信线程 |
| 请求队列、结果队列 | `transport/` | 调用方入队，通信线程出队 |
| 真实设备快照 `snap` | `device.c` 的 `Device` | 仅 `dev_on_result` |
| 当前动作计划 `plan`、待执行计划 `queued` | `device.c` 的 `Device` | 仅 `dev_*` 入口与 `dev_on_result` |
| 显示副本 `display`、乐观标志 | `session.c` 的 `Session` | 仅 `session_*` |
| 输入框文本、确认状态、提示文字 | `session.c` 的 `Session` | UI 事件处理 |
| 窗口尺寸、DPI、UI 内核指针 | `app.c` | 窗口过程 |

`device` 与 `session` 都只在 UI 线程被调用，不使用锁。`transport` 内部用临界区保护两个队列，调用方不加锁。

## 动作计划

计划是有序步骤数组，一次提交，逐步骤执行，同一时刻只有一个未完成请求。

```c
typedef struct {
    unsigned char func;          /* 3 读, 6 写单寄存器, 0x10 写多寄存器 */
    unsigned short addr;
    unsigned short count;        /* 读: 寄存器数; 写单: 值 */
    unsigned short values[2];
    unsigned char nvalues;
} DevStep;

typedef struct {
    DevStep steps[3];
    int count;
    int cursor;
    unsigned char verifyCount;
    unsigned short verifyReg[2];
    unsigned short verifyVal[2];
} DevPlan;
```

三类计划的组成：

| 用途 | 步骤 | 校验 |
| --- | --- | --- |
| 状态刷新 | 读 0–20 | 无 |
| 读取保护阈值 | 读 80–83 | 无 |
| 设定电压与电流 | 0x10 写 8 起 1 到 2 个寄存器 → 读 0–20 | 比较寄存器 8、9 |
| 输出开关 | 0x06 写 18 → 读 0–20 | 比较寄存器 18 |

读 0–20 的响应包含全部状态寄存器，数组下标等于寄存器地址，因此校验直接在响应数组上比较，不需要额外一帧单独回读。

## 数据流

1. 用户点击按钮，`app.c` 调用 `session_*`。
2. `session` 做前置检查（连接状态、输出状态、量程、输入格式），构造计划交给 `dev_*`。
3. `dev_*` 在空闲时立即提交第一步；忙碌时把计划放入 `queued`，当前计划结束后自动切换。
4. `transport` 的通信线程发出请求，收到回复帧后校验 CRC、从站地址、功能码与长度，通过则写入结果队列并置位结果事件。
5. UI 线程在消息循环中等待结果事件，被唤醒后调用 `session_on_result`。
6. `session_on_result` 调用 `dev_on_result`，执行器更新快照、校验写入、推进游标，若还有步骤立即提交下一步。
7. `session` 同步显示副本（乐观期间按一致性与错误判断是否回滚），调用 `dev_tick` 在空闲时补发状态刷新，最后触发重绘。

## 并发模型

全项目两个执行单元：

- UI 线程：窗口消息、计划推进、绘制。
- 通信线程：由 `transport` 在 `mb_start` 中创建，独占串口读写。

通信线程在没有未完成请求时阻塞等待事件，不空转。收到回复帧后立即回到取请求分支，因此请求之间没有固定等待。UI 线程用 `MsgWaitForMultipleObjects` 同时等待结果事件与窗口消息，不使用定时器。

## 事务时序

设定电压与电流的一次事务：

```
UI 线程                     通信线程                    设备
  |  提交 0x10 计划            |                          |
  |------------------------->| 写 01 10 00 08 00 02 ... |
  |                          |------------------------->| 约 190 ms
  |                          |<-------------------------| 回显
  |<-------------------------| 结果入队、置位事件         |
  |  提交 读 0-20             |                          |
  |------------------------->| 写 01 03 00 00 00 15 ... |
  |                          |------------------------->| 约 390 ms
  |                          |<-------------------------| 47 字节
  |<-------------------------| 结果入队、置位事件         |
  |  校验寄存器 8、9，结束     |                          |
```

实测总耗时 797 ms，共 2 帧。

## 显示副本

设备快照只在 `dev_on_result` 中更新，代表设备真实状态。显示副本由 `session` 持有，供绘制使用。

点击写入后，显示副本先填入目标值并置乐观标志。之后每收到结果，比较显示副本与真实快照的三个字段（输出状态、设定电压、设定电流）：

- 三者一致：清除乐观标志，显示「写入完成，回读值与目标一致」。
- 出现错误（超时、异常码、回读不一致）：清除乐观标志，显示副本回滚到真实快照。
- 超过 3 秒仍未一致：按回滚处理。

实测电压与实测电流不参与乐观显示，始终显示真实读数。

## 扩展点

- 新增寄存器写入能力：在 `device.c` 的 `dev_*` 入口增加计划构造函数，并在 `docs/PROTOCOL.md` 记录量纲。
- 新增设备型号：`DEV_V_MAX_MV`、`DEV_I_MAX_6A`、`DEV_I_MAX_12A` 与量纲函数集中在 `device.h` 与 `device.c`。
- 新增界面控件：在 `ui.cpp` 按四段结构（命中测试、状态记录、绘制、返回）扩展，业务代码不复制绘制逻辑。
- 更换传输介质：实现新的 `MbIo` 后端，`device` 与 `session` 无需改动。
